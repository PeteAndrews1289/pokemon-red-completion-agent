## Recording a deviation

Before materially changing stage order, scope or exit criteria, append a dated decision here:
the prior plan, evidence or user request, proposed change, effect on the end goal, costs/risks,
and the decision owner. Preserve the previous baseline file and create a new version if its
meaning changes. A small implementation choice within an existing milestone is not a new baseline.

After each completed work session, append a concise review to the roadmap state: result,
deviation (or none), and next step. Refresh again within a long session after a material verified
fit, gameplay result, capability or blocker changes the project position. No heartbeat or
minute-by-minute rewrites are needed. Missing new learning is a fact to show, not a reason to
move the goalposts.
