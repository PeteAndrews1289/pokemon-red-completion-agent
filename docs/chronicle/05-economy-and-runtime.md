# 5. September 11–15: money, reachability, and the cost of integration

[Previous](04-continuous-collection.md) · [Contents](README.md) · [Next](06-battle-classroom.md)

## A collector can make the wrong affordable-looking choice

On September 11 a learned acquisition choice reached Seafoam, spent its last
Great Ball and gained no registration. The run retained 443 actions, 21,408 frames,
the party's HP costs and 568 cash. One failed selected outcome was fitted,
moving that model's example count from 68 to 69.

The [resource-exhaustion report](../work-sessions/2026-09-11-collection-resource-exhaustion.md)
does not call this a funding success. A funding option existed but was not selected.
Nor does it invent an exception-level explanation that the failed run did not retain.

This is the practical meaning of learning from failure: the lesson and the lost
resources both survive. It does not mean accumulating failures alone establishes
competent collection.

## Money became a planning dependency

The work connected ordinary trainer income, transport, restoration and paid
collection opportunities. Fishing, Safari access, stone purchases and finite
trainer availability supplied different resource constraints.

Pete repeatedly challenged item sales as the default solution. The intended
direction was ordinary play and legitimate income, including eventual renewable
League earnings when the team could sustain them. The later record distinguishes
finishing the League from proving a profitable repeatable money cycle.

[Economy integration](../work-sessions/2026-09-10-economy-agent-integration.md),
[renewable funding](../work-sessions/2026-09-10-renewable-funding.md) and
[funded collection](../work-sessions/2026-09-11-funded-collection-overnight.md)
preserve different steps of that work. They are not all independent successful
funding trials.

## Reaching a location was not the same as executing its service

The September 12–14 records include fishing, fossils, storage, source menus,
supply admission and whole-catalog collection work. Repeated boundaries appeared:
a candidate was theoretically present but not reachable; a route reached a map
but not a usable interaction; an attempted action left dialogue or a battle pending.

A nonconsuming rehearsal was useful precisely because it could reject a bad
configuration before spending an actual game attempt. It was not itself training.
The [rehearsal report](../work-sessions/2026-09-14-nonconsuming-direct-rehearsal.md)
and [full-collector stop](../work-sessions/2026-09-14-model121-full-local-collector-stop.md)
show why preflight and gameplay outcomes must remain separate.

The recurring engineering question was whether to fix another specific boundary
or improve the shared contract. That tension is part of the project history;
not every repair instantly produced model progress.

## Battle execution needed evidence of the intended action

A September 15 audit exposed false success in move execution.
Seeing damage or returning to a menu was insufficient proof that the requested
move had actually been selected. Shared runtime checks were strengthened around
the original battler's complete PP vector, menu state and bounded settlement.

The [runtime refocus](../work-sessions/2026-09-15-battle-runtime-refocus.md)
records adversarial reproduction, a 108-case matrix, retained diagnostics and
review adjudication. Claude contributed useful criticism; some proposed examples
needed correction. Flash's initial response lacked the supplied context and
offered inapplicable advice. Those distinctions matter more than merely listing
which assistants were involved.

## Final Red completion was made explicit

The September 15 requirement remained stronger than a checkpoint demonstration:
one fresh model-directed Red playthrough, Champion and Hall-of-Fame evidence,
and the declared 124-species legitimate native route before a ROM hack.

A later Blue run and later-title acquisition can fill declared version, trading
and event gaps. That does not create local Red flags or excuse the fresh-run
requirement. Mew is deferred to a legitimate later source.

## What this phase left unresolved

A growing collection save demonstrated real capability, but broad runtime support,
resource sustainability and learned whole-battle execution still needed connection.
More tests and larger menus were useful only insofar as they enabled the player
to make and complete consequential decisions.

The next phase therefore built a more controlled classroom for battles while
keeping the actual game's resource and recovery consequences visible.
