# Clustered powered V2 capacity census

## Why this gate exists

The product is a transferable Pokémon agent that can finish stories and construct living
Pokédexes across titles. Red supplies the first causal curriculum; Crystal is the first transfer
falsifier. The immediate experiment cannot support that mission if it counts cloned saves or
multiple questions from one upstream episode as independent games.

The frozen V2 design therefore needs **139 unused authenticated upstream lineages** before new
collection begins:

- 36 train lineages supporting exactly 72 prospective selected-arm attempts;
- 100 untouched development lineages supporting one confirmatory question and four same-reset
  policy branches each; and
- three untouched pre-branch contingency lineages.

The design digest remains
`c20d2934e8f0632e6bb795ccc15cad2bb5aa9ee8330e08a755801344f9ca5b8d`.
This census does not change it.

## What the implementation can prove

The title-neutral capacity layer receives digest-only descriptions of unused authenticated
lineages. Each description retains immutable train/development ownership, a physical-root digest,
an independence-lineage digest, title-neutral pressures, and the genuine three-option scenario
templates that the root can expose. The Red adapter derives those descriptions from the existing
action-free provider compatibility inventory.

The aggregate gate checks:

- unique physical roots and upstream lineages;
- immutable train/development separation;
- 36/100/3 lineage and 72-attempt capacity;
- same-reset/RNG fork feasibility for development and contingency;
- every frozen focus-kind and candidate-position schedule;
- minimum semantic-family, menu-template, location, and pressure support; and
- exact question support for every row of an optional allocation witness.

Raw counts are deliberately insufficient. Even if an inventory exposes 139 roots, collection
stays closed until an exact 36-train / 100-development / 3-contingency witness satisfies all
simultaneous schedules and support floors. A malformed witness, partition crossing, missing
contingency, transfer-only Red kind, or changed kind/position schedule fails closed.

The three contingency roots are conservatively required to be development-owned and same-reset
capable. Training already tolerates up to 30 prospective setup-only terminals; the powered
development denominator is the quantity that cannot accept an unread invalid lineage without a
qualified replacement.

## What the command cannot do

The production command has no controller, action executor, root-claim writer, behavior draw,
teacher, outcome decoder, model scorer, fitter, allocation output, retry switch, or public path
surface. It binds the exact public design digest and executable source, takes a shared read-only
claim-registry lease, observes only still-unused nonsealed roots, and returns aggregate path-free
facts. Protected counters must remain zero.

An exact design-digest mismatch fails before private input authentication. An unexpected runtime
or integrity failure returns only a sanitized stage and zero-effect counters.

## Interpretation rule

This is a cheapest-falsifier gate, not a capability milestone:

- If any necessary capacity floor fails, that fact is decisive. Publish the aggregate deficit,
  close gameplay, and redesign the lineage supply rather than weakening the frozen endpoint.
- If all necessary bounds pass but no exact witness exists, capacity remains unproven and
  collection stays closed.
- Only a valid exact witness proves capacity. That permits one outcome-blind private freeze and a
  bounded train batch; it does not permit powered fitting, development opening, authority,
  sealed Red, Crystal, or a full-game replay.

The last published inventory saw only 59 eligible independent roots—36 source-train and 23
source-development—before later claims consumed additional contexts. Against V2, that historical
shape would be short 77 development lineages, all three development contingencies, and 80 total
lineages. This is a prior expectation, not the result of the new one-shot census. The private
inventory remains unopened until this implementation is published and exact-main CI is green.

## Engineering qualification

The first pull-request run passed source, documentation, registry, lint, and type gates, then was
canceled at the workflow's former 20-minute ceiling while pytest was still active. That was a
capacity problem in CI, not evidence that a behavioral assertion failed. The exact paired-test
calculations are now memoized with typed cache keys; regression tests prove that a cached numeric
result cannot admit a boolean or otherwise bypass the original validation boundary. The expanded
affected group completes locally in 17.98 seconds, and the complete qualified suite reports 5,894
passes, one expected xfail, three integration deselections, and one environment-bound local-runtime
deselection in 12m08s, restoring headroom under the unchanged 20-minute CI limit. These changes
affect engineering throughput only; the frozen V2 design, private-open rule, and every
protected-effect counter are unchanged.
