## What the model actually learned

The model ranks nine types of work from normalized campaign pressures and candidate-relative cost
and risk:

- advance story;
- acquire a species;
- develop the team;
- evolve a species;
- restore the team;
- resupply;
- manage storage;
- recover control; and
- explore.

It applies one shared linear scorer to every candidate. Its 35 inputs exclude title, map,
coordinate, objective, species, item, move, party slot, private binding and candidate position.
Unavailable choices receive exactly zero authority. A selected semantic index is rebound to a
title-private finite skill only after the model chooses.

This is the executive layer above destination selection and below the completion contract. It is
not a pixel-to-button foundation model, a complete route policy or an end-to-end Pokémon player.

## Why the result is credible

The curriculum was fixed before counted execution and rejected repeated semantic contexts,
train/validation overlap, weak multiway coverage, insufficient menu reversals and answer-position
collapse. Every selected skill completed an uncounted exact-state rehearsal before its one-shot
episode could be spent. Failed historical episodes remained failed rather than being retried into
success.

Promotion was a separate published source revision. It authenticated the historical training
registry, catalog, model and fit summary by digest. Shadow predictions could not change the
reference execution. Causal execution contained no teacher object or fallback callback. Every live
question and private binding manifest was rederived before action, and a separate verifier judged
the resulting mechanic. Inputs and ROM-adjacent files were rehashed after the batch.

The baseline comparison is also reported honestly. The model beat fixed priority 27/27 versus
15/27 (paired 12–0, p = 0.00048828125) and lowest effort 27/27 versus 16/27 (paired 11–0,
p = 0.0009765625). The strongest authored comparator, highest pressure, reached 25/27. A 2–0 edge
has p = 0.5, so the important next evidence is transfer or fresh-state behavior—not another claim
based on the same 27 examples.

## What remains before broad model training

The engineering substrate is strong, but “full model training” needs a larger claim than this first
ranker can support. Four gaps remain:

1. **Fresh-state generalization.** Red promotion reused the already-open validation contexts. Add
   preregistered perturbations or a genuinely new title; do not reuse the sealed destination test
   for this unrelated claim.
2. **Cross-title live qualification and actions.** Crystal's normalized goal evidence, source pin,
   banked party/Pokédex decoder, capability masks and private binding contract now exist, and the
   matching v1.1 owner ROM passes entry. The reads and a minimal set of real, independently verified
   bindings still require exact-commit live qualification.
3. **Online hierarchy integration.** The manager has controlled one bounded decision at a time. A
   long-running player must repeatedly observe, choose, execute, verify, recover and replan without
   a hidden route deciding when the manager is consulted.
4. **Living-Pokédex mechanics.** Full completion across games adds version exclusives, trades and
   trade evolutions, breeding, time-of-day encounters, roaming/static legendaries, one-time puzzle
   prerequisites, storage policy and coordinated multi-save state. These belong in title adapters
   and completion contracts, not in model identity features.

  navigation microtask with independent referees.

### Gate 2 — minimum executable Crystal slice

- Read actual Crystal campaign, party, collection, storage, supply and control evidence.
- Bind only mechanics that can execute and verify from authenticated nonsealed contexts.
- Run frozen-Red zero-shot first; classify failures by observation, availability, ranking,
  execution or verification layer.

### Gate 3 — sample-efficiency comparison

- Fit a fixed small Crystal adaptation set from the Red initialization.
- Train the same architecture from scratch on exactly the same examples and optimizer budget.
- Report accuracy, calibration, per-kind behavior and live execution—not only offline labels.

### Gate 4 — repeated online control

- Let the manager choose consecutive goals from changed states.
- Require bounded failure recovery and a new observation after every verified mechanic.
- Add recurrence or a nonlinear scorer only if the simple shared ranker fails a preregistered
  capability test; architecture size is not itself progress.

### Gate 5 — living-Pokédex expansion

- Add a species-obtainability graph per title/version and explicit source-of-truth provenance.
- Separate registration, living ownership, evolution readiness and level-cap goals.
- Model trades, breeding, one-time encounters and legendary puzzle prerequisites as capabilities
  and finite skills.
- Add multi-save coordination without leaking version or species identity into the portable goal
  selector.

## Recommended project narrative

The strongest job-search story is no longer “I scripted Pokémon Red.” It is:

> I built a deterministic expert and verified mechanics for a 47-million-frame Pokémon Red run,
> then treated that expert as a data generator rather than the final product. Failed pilots showed
> that different save files were not necessarily different lessons and that a sensible high-level
> choice could still hide an impossible long skill. I added prospective semantic curriculum gates,
> exact-state full rehearsal, one-shot collection, leakage-resistant shared-candidate features and
> independent outcome verification. The first real manager learned 54 cartridge-derived choices,
> scored 27/27 on development validation and then controlled 27 live Red mechanics with no teacher
> fallback. The next experiment freezes that Red representation and asks whether it reduces the
> teaching required in Pokémon Crystal.

That narrative demonstrates experimental design, failure analysis, reproducible ML, systems
engineering and calibrated claims. Crystal transfer is the next decisive portfolio result because
it can distinguish a portable abstraction from a polished one-game curriculum.
