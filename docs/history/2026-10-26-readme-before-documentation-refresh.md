# Pokémon Red Completion Agent

A Pokémon player that learns which goals to pursue and how to fight, using deterministic game-control skills to execute its choices.

**Active development, not a finished autonomous player.** Red is the first target. The eventual aim is transferable play and one shared, verified registered Pokédex.

## What is not solved

The private assembly is packaged; its shared environment is pinned,
not distributed. The guarded ordinary-wild boxed-loan recovery now passes related
copies and the actual retained recovery, without adopting the trainee's role. The161-example goal
model has useful healing learning but thin readiness/resource/capture coverage;
its scores are not calibrated confidence.

Full fresh-game autonomy and transfer remain unfinished. Fresh handoff and guarded
capture-miss recovery pass; the early next-menu gate is repaired. Fresh completion is unproved.
Direct challenge/loss/gap signal exists,but unseen transfer/stopping is unproved.
No battler redesign.

## How it works

Semantic emulator observations → learned goal choice → bounded skill execution →
verified result → retained continuation. Training is an explicit separate process;
ordinary play does not automatically update model weights.

Python, PyBoy, NumPy and SQLite support the player. Navigation, menus and other
declared mechanics are deterministic. Coding assistants develop the software;
they do not secretly choose each live game action. This is not pixel-only play.

**Red first:** one fresh model-directed story and 124 legitimate same-save
registrations, then a compatible unfamiliar hack, Crystal and at least Emerald.
Version/trade/event dependencies stay explicit for later legitimate acquisition.
The target is registrations, not a simultaneous living dex.
