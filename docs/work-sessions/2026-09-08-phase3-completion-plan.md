# Phase 3 sustained-Red work plan

User direction: continue through bounded sessions toward the existing Phase 3
exit, using Claude and Antigravity where useful. Do not substitute tests,
documentation or a single evolution for sustained model-directed play.

## Six-part mission check

1. Capability: maintain collection progress through navigation, encounters,
   resource changes and safe recovery, preserving every required living specimen.
2. Learned authority: the model keeps actual destination/native-goal choice;
   deterministic execution repairs unblock those choices rather than replace them.
3. Transfer test: vary Red opponents, resources, regions and goal types. This is
   correlated development, not independent generalization or cross-game transfer.
4. Cheapest falsifier: reproduce the field/battle finisher mismatch in the real
   ROM-free training loop, then verify a bounded exit from the retained failure.
5. Time box: reassess each repair after two hours; audit each completed gameplay
   chain. Continue the next justified session under the user's phase-completion
   request rather than wait for another routine approval.
6. Stop condition: stop an individual attempt on unsafe/unsupported control or
   lost evidence; never retry its consumed choice. Reorient before a new bounded
   repair or continuation. Stop the phase only when its exit is actually met or
   progress genuinely requires new authority or unavailable external input.

## Existing exit and prospective demonstration

The baseline remains: repeated multi-goal progress across varied Red situations,
with measured costs, interventions and recovery. Story completion, end-to-end
learned battle control and independent transfer are not claimed by this stage.

Use at least two linked chains of at least three actual model-selected goals,
covering multiple regions and at least three supported goal kinds. Require
verified living-collection gains, retained failures/costs, legitimate recovery,
and post-fit continuation. A chain dominated by easy repeated healing without
collection progress does not satisfy the exit. Forced support adds no learned
labels. These are prospective evidence requirements, not a new success percentage;
reviewers must challenge whether the resulting evidence supports the baseline.

## Execution sequence

1. Repair encounter/resource readiness and bounded escape; reproduce the actual
   mismatch with varied ROM-free cases. Keep safety limits and legacy behavior.
2. Validate the exact retained failure state and a finite recovery operation.
   Preserve the original failed episode and all its costs. No silent quantum
   rewind and no diagnostic-state admission by declaration alone.
3. Reconnect the recovered safe endpoint to authenticated bounded learning.
4. Run and audit model-selected collection/evolution/resource continuations;
   refit only admitted actual outcomes and retain all prior fitted rows.
5. Assess repeated chains against the unchanged Phase 3 exit. If unmet, name the
   smallest remaining capability and continue a bounded session.
6. Publish source/evidence/documentation in coherent batches. Existing CI is a
   publication check, not a serial wait before each routine development lesson.

## Reviewer ownership

Codex owns code, tests, state handling, gameplay, fitting and publication.
Claude independently challenges recovery safety, failure admission and tests.
Antigravity Flash High challenges missing adversarial cases and phase-exit claims.
Reviews use exact source snapshots/public-safe packets, never live/private state.
Any test draft is isolated; neither reviewer edits the active checkout or runs
the game. Record accepted/rejected findings with reasons. Query provider usage
before/after reviews; unavailable data is not inferred from model self-reports.
