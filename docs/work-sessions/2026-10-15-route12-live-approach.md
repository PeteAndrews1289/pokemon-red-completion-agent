## Windows desktop assessment and next-day handoff

The current machine reports an Apple M1 and 8 GB RAM. The planned desktop has
32 GB RAM (four times as much), a Ryzen 9 9900X with 12 cores/24 threads, a
16 GB RTX 5060 Ti, and a 2 TB internal SSD. More memory and CPU capacity should
help concurrent tests, emulator copies and analysis; internal storage should
reduce external-drive overhead. These are expectations, not measured speedups.
[AMD specifications](https://www.amd.com/en/products/processors/desktops/ryzen/9000-series/amd-ryzen-9-9900x.html).

The active goal and battle models use NumPy. They do not automatically move onto
CUDA because an NVIDIA GPU is present. The 16 GB GPU offers room for future
GPU-backed training, but converting the learner is not part of this repair and
is not required to finish Red. Hardware does not correct execution logic or make
hosted coding-assistant inference run locally.
[NVIDIA specifications](https://www.nvidia.com/en-us/geforce/graphics-cards/50-series/rtx-5060-family/).

Recommended transfer sequence, not executed here:

1. Keep the Mac/T7 originals available. Do not reformat the APFS drive or assume
   Windows can directly use it. Transfer over the network from the Mac, or make
   verified copies onto a separate Windows-readable transfer device.
2. Copy the entire current checkout, including uncommitted/untracked work, plus
   its private helper/model/data dependencies, protected saves and failure
   receipts. A clone of the published repository alone is not the current player.
3. Use WSL2/Ubuntu and keep the working tree, Python environment and active logs
   inside its Linux filesystem on the internal SSD, rather than under `/mnt/c`.
   This follows Microsoft's file-performance guidance, not a requirement to
   replace Windows. [WSL filesystem guidance](https://learn.microsoft.com/en-us/windows/wsl/filesystems).
4. Rebuild the Python environment for Linux/x86-64; do not copy the Mac virtual
   environment as executable software. Rebind absolute paths and make a new
   platform-specific frozen package. Keep old manifests as historical evidence.
5. Verify file hashes, relevant tests, isolated imports and a short copied
   emulator/policy-parity check before a fresh official run. Begin with two
   emulators and measure CPU, memory and I/O rather than assuming a safe maximum.

Windows migration is a separate platform qualification, not fresh gameplay proof.
