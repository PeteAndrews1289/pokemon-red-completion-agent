## Delivered

The opt-in shared capture entry accepts an encounter-wide ball allocation and an
explicit replacement selector. It uses the existing native forced-party executor,
then checks target identity/HP, original party/PP, collection, bag and map/money.
It never chooses an attack, Run or another ball. No replacement is spent after
the last authorized throw. Ordinary capture behavior is unchanged.

Throw commitments precede input and survive exceptions in the caller-owned
budget object. Resume requires the same request, allocation and observed ball
count. A partially interrupted selection pauses rather than receiving a free
retry. Persisting/authenticating this object with the retained save belongs to
the caller; it is not itself a save-provenance system.

Status preparation can explicitly preserve a healthy active member above half
maximum HP and with at least half the healthiest catcher's current HP. This
avoids an unnecessary switch without automatically leaving a fragile full-HP
helper exposed. The legacy default is unchanged. This rule is support, not
learned strategy or a survival guarantee.
