# Collection travel access

## Mission check

- Capability: reach useful collection and evolution destinations using observed legal Fly travel plus cartridge-derived walking, without per-species routes.
- Learned authority: broaden the existing goal/destination menu; Fly remains deterministic transport, not a reward-generating goal. Fit only actual eligible model choices.
- Transfer test: vary visited towns, carrier slots, landing coordinates, onward paths and stale observations in ROM-free tests. Red execution is one correlated lineage, not cross-title proof.
- Cheapest falsifier: from native110's retained Route22 endpoint, qualify a reachable evolution destination, then a short model-selected continuation. Preserve the ledger and resource costs.
- Time box: one session, two hours. Prefer existing controller/composer seams; stop architecture work once a bounded live opportunity can be tested.
- Stop condition: no guessing landings, trial confirmation, unsupported field mechanics, fabricated successful routes, lost specimens or consumed-trial replay. If travel fails, retain and diagnose that failure before continuing.

## Implementation plan

1. Decode Fly landing coordinates from the pinned cartridge table; do not transcribe town coordinates into a route.
2. Reuse the observed-menu Fly controller and routed-goal composer, with a checked landing followed by the computed walking plan. Keep the ordinary walking path preferred where available.
3. Add opt-in routing scope, action-free readiness and stale-state/budget tests. Then one published executable and short real continuation; no hosted-CI wait in the gameplay loop.
4. Audit outcomes, refresh the dashboard evidence and roadmap/handoffs/narratives, and select the next useful step from measured results.

The previous batch is closed: 110 examples, 40 specimens, 32 living species. It is not replayed.
