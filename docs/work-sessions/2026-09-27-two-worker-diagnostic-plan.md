## Mission check

1. Capability: isolated, reproducible concurrent scenario execution and error retention.
2. Learned authority: unchanged. Maintenance unblocks the named six-battle comparison
   of the existing risk/cost battler; only that frozen actor chooses battle actions.
3. Transfer: two party configurations and three timing offsets are correlated diagnostics,
   not independent held-out qualification. Two separately initialized openings test mechanics.
4. Cheapest falsifier: ROM-free process isolation tests, then the six Misty battles.
5. Time box: 90 minutes engineering/verification; 600 seconds each native batch.
6. Stop: any isolation/hash/retention failure stops new dispatch. Do not expand another
   learner, route system or controller architecture to make the screen succeed.

  Whole-team victory is the outcome. Prepared>=2/3 and >=2extra wins versus current is
  only a local signal; no automatic adoption, fit or training-row admission.
- Fresh starts: two new DEVELOPMENT smoke identities with extra boot frames257/293.

  Existing deterministic opening/rival teacher, explicitly zero learned choices.
  Each:450actions,80000frames,180seconds;600seconds batch. No snapshot loading,
  memory edits, retries, source allocation as TRAIN, or full-game continuation.
- Invalid worker exit/timeout stops pending work and drains already-active bounded workers.
  Interrupt cleanup first; escalation only for the exact processes this runner spawned.
  Record observed exits, never imply that a killed run retained a valid terminal.
- Independent zero-input audits of battle choices, endpoints, opening receipts and source
  protection. No save copy-back, campaign writes, model edits, publication or deployment.

Reassess after these eight attempts or the first infrastructure failure. Native throughput
and implementation effort are reported separately; concurrency does not itself teach the model.
