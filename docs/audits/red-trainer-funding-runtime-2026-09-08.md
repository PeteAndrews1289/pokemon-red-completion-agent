offsets at sprite8 and above lose their byte carry through `%8`. The cartridge
[trainer macro](https://github.com/pret/pokered/blob/master/macros/scripts/maps.asm)
stores an adjusted base pointer plus the full trainer-bit offset. Correcting this
needs a test crossing the byte boundary and explicit historical-menu compatibility.
It did not explain this sprite5 failure. Do not expand funding across those slots
using the current decoder. The earlier four-candidate static inventory is provisional.
