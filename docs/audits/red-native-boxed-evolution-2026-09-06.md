## What changed

- Native routing connects the existing evolution provider to actual Center boundaries. It never
  fabricates a destination observation; the destination skill rebinds after arrival.
- An explicit profile transition preserves old checkpoint verification, adds the existing
  canonical level-evolution mechanic and removes arbitrary party grinding. The named target
  is configured scaffolding, **not learned species-target selection**.
- Existing PC and participation-training code is reused. Native eligibility requires exactly
  two precursors (the existing engine's supported duplicate case), keeps a living precursor,
  and rejects low-level candidates with no supported training venue. Three-plus duplicates
  are currently masked rather than falsely claimed supported.
- The trainer now honors the caller's smaller evolution battle/step limits: 32 battles and
  2,000 seeking steps for this integration, inside existing action/frame limits.
- Both continuations used four-decision maximums, 6,000 actions / 600,000 frames per decision;
  actual total was only **472 actions / 21,216 frames**. They stopped well before those caps.

## Reorientation and candid feedback

Useful memory-aware play remains **2/5 (40%)**. V2 now fits actual native observations, but we
have not shown it learning an effort-sensitive switch or completing both useful alternatives.
No stage exit or long-term goal changed.

The useful lesson for development is that a callable skill with unit tests is not necessarily
an end-to-end usable skill. The bottleneck is now a small live execution mismatch, not another
learner design. Next session should reproduce that mismatch from the saved Center boundary,
qualify one complete evolution, then resume a short measured learning loop. If it expands into
route-specific patching, stop and reassess. No additional features or teacher factory are needed.
