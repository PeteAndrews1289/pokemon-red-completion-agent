text border, but sprite identity0 rather than1; pending trainer identity is absent
and battle state is0. Pinned cartridge code explains a legitimate intermediate:
[DisplayTextID](https://github.com/pret/pokered/blob/1e96034092686d006e863cace09e87273051a3d8/home/text_script.asm)
calls initialization before copying the trainer sprite ID.
[DisplayTextIDInit](https://github.com/pret/pokered/blob/1e96034092686d006e863cace09e87273051a3d8/engine/menus/display_text_id_init.asm)
draws the border before returning. The snapshot is consistent with that interval;
it does not identify the precise CPU instruction. A visible box is not necessarily
an input-ready interaction.

The validator now raises a specific initialization signal only for sprite0 and
no pending identity, after every other context, event, party, resource and
readiness guard passes. Only the fresh owned-trigger loop catches that signal,
spending its existing maximum24 WAIT12 actions. It never repeats the triggering
movement. Wrong identity and changed protected state still abort immediately.
Dialogue confirmation still requires the exact nonzero trainer sprite, including
after an earlier successful validation. Retained-state recovery does not silently
accept initialization or acquire new execution authority.
